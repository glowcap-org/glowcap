# glowcap — Agentic Infrastructure

Canonical home for agent-facing guidance in this Zig repository.

## Layout

```text
.agents/
├── README.md   # this file, with an index generated from the files it lists
├── rules/      # one .md per rule — see the Rules table
├── skills/     # one directory per skill, each with a SKILL.md — see the Skills table
├── personas/   # anonymous taste lenses (slug.md) — see the Personas table
└── hooks/      # shared hook scripts, see the Hooks table
```

`zig build gen-agent-index` generates the index below from each rule's, skill's,
and persona's frontmatter `description` (a hook's first comment line), so a
file's purpose has one home, and `source-check` fails when the index is stale.
A named person or person-named slug lives in an unpublished persona source,
never here. [`personas/README.md`](personas/README.md) gives the lookup order.

Tool overlays point back to the canonical rules here and duplicate nothing:

- `.claude/rules` is one directory symlink to `.agents/rules`.
- `.cursor/rules/<name>.mdc` is one symlink per rule because Cursor discovers
  rules by `.mdc` file.
- A rule is resident (`alwaysApply: true`) or scoped. A scoped rule names its
  files twice, as Cursor's `globs:` and as Claude's quoted `paths:` list,
  because Claude ignores `globs:` and would otherwise load the rule into every
  session. `source-check` holds the two lists equal.
- `.claude/skills` and `.cursor/skills` are directory symlinks to
  `.agents/skills`.
- Codex reads `AGENTS.md` and `.agents/skills` directly, and `.codex/README.md`
  records that no `.codex/skills` mirror is needed.

`zig build source-check` verifies this topology and every scaffolding claim it
can reach mechanically, among them symlink shape, the rule and skill indexes,
Markdown links, documented build steps, and doc kinds.
[`tools/check/source_check.zig`](../tools/check/source_check.zig) is the
inventory. Update it in the same change as any scaffolding move.
