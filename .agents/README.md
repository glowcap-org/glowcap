# glowcap — Agentic Infrastructure

Canonical home for agent-facing guidance in this Zig repository.

`zig build gen-agent-index` generates the index below from each rule's and
skill's frontmatter `description` (a hook's first comment line), so a file's
purpose has one home, and `source-check` fails when the index is stale.

Each harness reads these files through its own overlay. Edit here, never
through a symlink, because an in-place edit turns the link into a file:

- `.claude/rules` is one directory symlink to `.agents/rules`.
- `.cursor/rules/<name>.mdc` is one symlink per rule because Cursor discovers
  rules by `.mdc` file.
- A rule is resident (`alwaysApply: true`) or scoped. A scoped rule names its
  files twice, as Cursor's `globs:` and as Claude's quoted `paths:` list,
  because Claude ignores `globs:` and would otherwise load the rule into every
  session. `source-check` holds the two lists equal.
- `.claude/skills` and `.cursor/skills` are directory symlinks to
  `.agents/skills`. Codex reads `AGENTS.md` and `.agents/skills` directly.
- `.claude/settings.json` and `.cursor/hooks.json` run the edit hooks under
  `hooks/`. `.mcp.json`, `.cursor/mcp.json`, and `.codex/config.toml` start
  Serena and the glowcap MCP server through `glowcap-dev`.

`zig build source-check` holds this topology: symlink shape, hook and MCP
wiring, frontmatter, the index, and links.
