# Reader voice: write it the way a person would

[doc-voice](../../rules/doc-voice.md) sets the bar. `source-check` holds the
mechanical part on the reader pages (`reader_scopes` in
`tools/check/source_check/docs/voice.zig`) and the Rooms text catalog:
no semicolon, no em dash, no word in `insider_words`
(`source_check/docs/reader_voice.zig`), and sentences of 250 characters or
fewer. A green check is the floor. This procedure covers the judgment the
check cannot make.

## Find

Scan wider than the check. Its word list holds only words that are never the
reader's, but most insider talk is an ordinary word used our way. Look for:

- names we give parts of the UI or system (rail, pane, front, sidecar)
- internal state and process words (intent, custody, journal, evidence,
  matrix, ladder, gate, boundary used as a noun)
- spec voice: a noun stack where a person would use a verb ("submitted
  storage execution")
- strings a screen reader speaks, which count as prose (`aria-label` text and
  the `...Said` helpers in `apps/rooms/lib/text/`)
- comparisons that claim something is new
- narrative the page does not need: build history, progress told as prose,
  a fact repeated, a pile of related-page links
  ([doc-voice](../../rules/doc-voice.md#narrative))

## Classify each hit

- **The reader's word.** OCapN, CapTP, and library terms the reader has to
  learn (vat, sturdyref, settle, seat, durable). Keep it, and say what it
  means the first time.
- **An on-screen label.** Use its exact text in bold. Read the label from
  `apps/rooms/lib/text/`, not from memory or a component name.
- **Ours.** Replace it with what the reader would call the thing. The sidebar,
  not the rail. A Rust library, not the sidecar. If the plain version is
  unclear, read the code to learn what the thing does, then say that.

Every rewrite stays true. Check a reworded claim against its source before
keeping it, for example what `reset` takes or what a session link's
permissions allow. Plain and wrong is worse than stiff and right.

## Rewrite

- Split a semicolon into two sentences. Read every split, since a mechanical
  pass gets a few wrong.
- A list of fragments drops its end punctuation instead of gaining periods. A
  list of full sentences gets capitals. A table cell that loses its subject
  gets one back ("It implies `async`.").
- Comparisons name the familiar precedent first, then the difference. Say
  "IRC clients have done this for years, and here is what differs", not "no
  other chat app can". If nothing differs, leave the claim out.
- Generated blocks (`GENERATED by` markers) are fixed at their source, then
  regenerated with their `gen-*` step.
- Contributor pages (`CONTRIBUTING.md`, `ui/README.md`, ADRs, `docs/`,
  `bindings/proofs/`) may keep working words. `contributor_scopes` in
  `voice.zig` still holds them to the punctuation rule.

## Hold it

- Add a file to `reader_scopes` once it is clean.
- Add a word to `insider_words` only if no reader page could ever need it.
- Plant a defect in a scratch copy to prove a new check catches it, then
  restore and `cmp` the file. Use `command cp -f`: an interactive `cp` alias
  skips the restore silently.
- Gates: `source-check`, plus `site site-render-check` for site pages,
  `gen-site-examples-check` for snippets, and `rooms-server-test` when Rooms
  text changes.
