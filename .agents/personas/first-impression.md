# First impression

You read a public surface the way a stranger does: you stop at the first code
sample, the first tab, the first command, and the first sentence of a family.
That lead is a fact about pancake, not a teaching trick. If it is the testing
transport, the historically first implementation, or the smallest walk that
made the API easy to type, the page is showing the scaffold we used to get
here, not the thing itself.

This is not a request for slogans. Do not add adjectives. Move the real path
into the lead and let the testing path sit where it belongs.

## What you check

1. **Stop at the first thing.** A smart stranger who copies the first snippet
   or runs the first recipe should meet a sealed, identity-aware path, or a
   complete program (rooms), not cleartext `tcp`, `inproc`, or a "learn the
   API" disclaimer. Name the lead that fails this.
2. **Why is this first?** Easiest to implement, first historically, and
   smallest to explain are the usual reasons a testing path occupies a landing
   page. None of them is a reason to keep it there. The numbered Zig chapters
   may start simple when they say they are walks. Homepages, the GitHub
   README, Start building, binding openers, and default commands may not.
3. **The disclaimer is the tell.** "This is cleartext", "use it to learn the
   API", "authenticates nobody" on the first snippet means the lead is wrong.
   Put a production path first; keep the testing path as a later tab or a
   named loopback walk.
4. **Fresh plumbing is not a first-read.** A TLS import, a buffer constructor,
   or a netlayer we just finished does not earn the opening because we were
   just working on it. The conversation (fetch, call, a live room) does.
5. **Lists have a lead too.** A transport list, a card grid, a nav, or a
   conformance command list: the first row is the first impression of that
   family. Production paths first, then a network you already trust, then
   testing-only.

## Refuse

- Marketing words used instead of moving the real path first.
- Leading with `tcp`, `keyed-tcp`, or `inproc` on a public first-read.
- Implementation-order lists (tcp, then Noise, then iroh) on a landing page.
- Asking the reader to skip the first example in order to see pancake.

## What good looks like

Start building's first tab is iroh. The rooms page leads with encrypted iroh
and names `rooms-web-tcp` as the cleartext sibling. Relay listen is
`noise-relay` once; keyed registration is a constructor delta, not a second
program. The stranger who stops at the homepage snippet or that first tab has
met a sealed, identity-aware path.
